# Ночная автоматизация: скрипт + расписание + грабли

## Состав
- `nightly_report.sh` — каркас: валидация данных → headless-агент → доставка в мессенджер.
- `com.example.nightly-report.plist` — шаблон launchd (macOS). На Linux — обычный cron.

## Принципы
1. **Сначала валидация, потом отчёт.** Упала свежесть витрин — приходит алерт, а не отчёт с протухшими цифрами.
2. **Минимальные права.** Агент по расписанию: read-only к базе + отправка в ОДИН конкретный канал. Не больше.
3. **Промпт отчёта — в файле** рядом со скриптом: версионируется, ревьюится, меняется без правки кода.

## Грабли macOS (сэкономят вам день)
- **Exit-код 78 без единой строчки лога** = launchd-процесс упёрся в TCC: фоновым процессам закрыты `~/Downloads`, `~/Documents`, `~/Desktop`. Рабочие файлы — в `/tmp` или `~/.local/`, логи — туда же. `StandardOutPath`/`StandardErrorPath` в plist указывайте В НЕЗАЩИЩЁННУЮ папку, иначе не увидите даже причину падения.
- **Настройки сессии PostgreSQL теряются** за пулером (PgBouncer): `options` из startup-пакета молча выбрасываются. Таймауты — через `ALTER ROLE`, не через строку подключения.
- **«Самолечение» стройте на скучном launchd/cron** со сторожевым таймером, а не на фоновых задачах самого агента: чем тупее инфраструктура, тем надёжнее.

## Установка (macOS)
```bash
cp com.example.nightly-report.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.example.nightly-report.plist
# проверить: launchctl list | grep nightly
```
